Всем привет!

Ищу желающих трудоустроиться в EPAM на Junior-позицию в проекты с JS (а также Java или .NET), где код пишется AI-агентами типа Claude Code, Codex, Kimi, Cursor.

## Интро

Меня зовут Дима Воробей. Я организатор RS School и Senior Engineering Manager в EPAM Systems.
Исторически EPAM годами нанимал и продолжает нанимать выпускников RS School, но пока не на так называемые "AI Native или AI Factory" проекты. Я хочу это изменить.

Сейчас в EPAM есть категория проектов, где практически 100% кода пишется AI, а команда инженеров отвечает за процесс поставки и результат.
Сами проекты — это достаточно стандартные веб-приложения для бизнеса, написанные на привычных JavaScript, .NET или Java.
Одно из основных отличий в том, что весь процесс разработки (от тикета до PR) выполняют кодинг-агенты типа Claude Code / Codex / Kimi / Cursor по специальному протоколу/процессу (буду называть его AI Factory) с контрольными точками, где ключевые шаги утверждают инженеры.
Не путать с AI Dark Factory (где этот процесс идет без контроля со стороны людей).

Термин "открытая Junior-позиция" для упомянутых выше "AI Native или AI Factory" проектов не совсем верен.
Открытого набора, как это было раньше, нет. Джуниоров на рынке труда тысячи, по резюме все одинаково прекрасны, часовое техническое интервью не показывает реальную картину и знания, да и у членов команд банально нет времени и желания разбирать этот поток кандидатов — проще нанимать мидлов или сеньоров из числа сотрудников EPAM.

С другой стороны, у RS School за эти годы накопились репутация и доверие, поэтому мы договорились с проектами, что я нахожу подходящих кандидатов и привожу их на входной фильтр проекта.
Для начала это будет пять человек, и если первая пятёрка пройдёт успешно, то мы расширим набор и географию, так как проектов, работающих по процессу AI Factory, много.

Так как я всегда был оптимистом, то надеюсь, что эти 5 человек успешно трудоустроятся, а для RS School это будет хорошим поводом сделать курс по разработке с помощью AI, опираясь на конкретные требования проектов, процесс разработки и возможности для трудоустройства.

## Как устроен отбор

Отбор на проекты устроен в несколько шагов, и путь одинаковый для всех (как для сотрудников EPAM, которые раньше не работали по процессу AI Factory, так и для внешних кандидатов).

1. Тестовое задание с моей стороны — **оно перед вами, в этом репозитории**. Как его делать — в [ASSIGNMENT.md](ASSIGNMENT.md).
2. Оформление в EPAM на позицию student, если вы еще не в какой-либо из учебных лабораторий EPAM (JS, Java или .NET). Статус student — это по факту просто доступ к инфраструктуре EPAM и учебным материалам/инструментам без зарплаты.
3. Второе тестовое задание на 2–3 недели. Задание на специально сгенерированном моковом проекте. Проект намеренно неидеальный, с типичными для реальных кодовых баз проблемами: тут проверяется не умение писать с нуля, а умение разобраться в чужом коде и валидировать то, что выдаёт агент. Период тестового задания не оплачивается. Задание представляет собой серию учебных юзер-стори, которые вы должны заимплементить вместе с кодинг-агентом. Первые несколько вы делаете, как вам удобно, остальные — по протоколу AI Factory (на этом этапе даются конкретные инструменты EPAM).
4. По результатам шага 3: если всё хорошо — рассмотрение на конкретный проект. Стек проектов обычно смешанный, вида React или Angular плюс .NET или Java. Бывает Full Stack JS.

## Требования

- Проживание в одной из стран: Грузия, Узбекистан, Казахстан, Кыргызстан, Армения. Первые 5 наймов — только из этих локаций. В дальнейшем я надеюсь, что найм будет доступен для жителей Беларуси, Украины или Польши.
- Английский — уверенный B1, лучше B2.
- Уверенное знание одного из доменов: JavaScript/TypeScript, .NET или Java. На самих проектах сейчас фронтенд — React или Angular, бэкенд — .NET, Java или Node.js. Достаточно одного стека глубоко.
- Понимание, как full-stack приложение работает end-to-end. Это не значит, что вы можете написать всё руками с нуля — это значит, что вы знаете основы и готовы быстро учиться.
- База инженера: Git, CI/CD, таск-трекеры (Jira или аналоги), общее представление о том, зачем нужны облачные провайдеры (AWS, GCP, Azure).
- Платная подписка на кодинг-агент (Claude Code, Cursor, Copilot или аналог). В 2026 году это необходимая база — без неё не получить нужный опыт. Помочь с подпиской на этом этапе мы не можем и ожидаем, что она у вас есть.
- База по AI: понимание, что такое LLM, harness, плюс практический опыт работы с кодинг-агентом.

# Техническая справка: BrownEvents (.NET)

Conference management application — the .NET version of the BrownEvents brownfield reference project.

**Stack:** ASP.NET Core 6 · EF Core 6 · PostgreSQL 14 · React 18 · Vite

## Quick Start

```bash
docker-compose up --build
```

| Service | URL |
|---------|-----|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:5000/api |
| Swagger UI | http://localhost:5000/swagger |

The backend seeds demo data (3 conferences, 7 sessions, 3 speakers) on first startup.

## Development Setup

### Backend

Requirements: .NET 6 SDK, PostgreSQL 14

```bash
# Start only the database
docker-compose up postgres -d

# Run the API
cd backend
dotnet run --project BrownEvents.Api

# Run tests
dotnet test BrownEvents.Tests
```

### Frontend

Requirements: Node.js 18+

```bash
cd frontend
npm install
npm run dev   # proxies /api to localhost:5000
```

## Project Structure

```
backend/
  BrownEvents.Api/          ← ASP.NET Core Web API
    Controllers/            ← HTTP layer
    Services/               ← business logic
    Models/                 ← EF Core entities
    Data/                   ← DbContext + DataSeeder
  BrownEvents.Tests/        ← xUnit unit tests

frontend/
  src/
    pages/                  ← React page components
    components/             ← shared UI components
    api.js                  ← HTTP client
```
